# PRD 总结与实施范围

## 一句话定位

基于多模态大模型与 Coze 工作流的轻量化餐食结构分析 Web Demo：用户上传餐食图片，确认或修正识别结果后，获得亲切、易懂、可执行的膳食结构评价与调整建议。

## 用户问题

1. 传统饮食记录依赖手动搜索和填写，记录成本高。
2. 普通用户看得出“吃了什么”，但不容易判断主食、蛋白质、蔬菜等搭配是否合理。
3. 泛化的“少油少盐、均衡饮食”建议难以直接行动。

## 产品原则

- 降低记录门槛：以图片上传作为主要入口。
- 先识别、再确认、后分析：用户修正结果优先于 AI 初始识别。
- 结构优先：聚焦主食、蛋白质来源、蔬菜及明显的烹调方式。
- 不伪精确：首版不输出缺乏可靠依据的克重、热量及营养素数值。
- 建议可执行：明确指出哪里需要调整，以及可以怎样替换或补充。
- 语气友好：面向一般用户，亲切但不使用特定年龄称呼。
- 承认不确定性：图片模糊、食物遮挡或隐藏配料无法判断时，不强行推测。

## PRD 中的完整产品闭环

上传图片 → 图片校验 → AI 识别餐食 → 用户确认/修正 → 膳食结构分析 → 生成建议 → 展示结果 → 保存记录 → 查看历史记录。

## Web Demo v0.1 范围

### 必须实现

1. 上传 JPG/PNG 餐食图片并预览。
2. 校验文件类型、大小及基础可用性。
3. 通过 HTTP API 调用 Coze 工作流。
4. 展示加载、超时、失败和重新分析状态。
5. 展示结构化结果：识别食物、膳食评价、主要问题、调整建议。
6. 输出使用亲切、易懂、非恐吓式语言。
7. 提示图片判断局限与一般性饮食参考边界。

### 条件允许时实现

1. 识别食物列表的修改、删除与补充。
2. 将修正后的食物列表重新提交分析。
3. 保存最近若干次本地分析结果。
4. 收集“有帮助/没帮助”和错误识别反馈。

### 暂不实现

1. 微信登录与微信用户身份绑定。
2. 小程序相机/相册权限流程。
3. 正式云数据库和跨设备历史记录。
4. 长期饮食趋势总结。
5. 减脂、增肌等个性化目标。
6. 精确克重、热量和营养素估算。
7. 疾病诊断或个体化医疗营养建议。

## 待补充的产品定义

- 优先用户与最常见使用场景。
- 营养分析所依据的知识来源和规则。
- 结构化输入/输出字段定义。
- AI 评测指标与通过标准。
- 图片存储、删除、隐私和数据保留策略。
- Coze 调用成本、响应时间、超时与重试策略。
- 健康内容安全规则和高风险问题拦截。

## 实施顺序

1. 获取 Coze 工作流的 API 输入、输出与调用示例。
2. 确认现有工作流能否拆分为“识别”和“分析”两个阶段。
3. 固定 JSON 输出结构和错误状态。
4. 使用 Streamlit 完成上传、调用和结果展示。
5. 增加用户修正与二次分析。
6. 建立小规模评测集，记录识别错误和建议质量。
7. 部署公开 Demo，补充 README、演示视频和项目复盘。

## 项目称谓

不建议称为“我做了一个简单模型”，因为项目没有训练新的模型。推荐称为：

- “基于多模态大模型与 Coze 工作流搭建的 AI 饮食分析 MVP”；或
- “轻量化 AI 餐食结构分析产品原型”；或
- “基于现成模型能力完成的概念验证（POC）”。
