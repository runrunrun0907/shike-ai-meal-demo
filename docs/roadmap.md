# AI 饮食分析 Web Demo 路线图

## 优先级说明

本项目保留两套优先级：

- 原 PRD 的 P0/P1/P2：面向完整微信小程序的产品规划。
- 当前 Demo 的 P0/P1/P2：面向可快速验证、可公开演示的 Streamlit Web MVP。

开发阶段以“当前 Demo 优先级”为执行依据。完整小程序规划保留，不代表删除，仅延后实现。

## Demo P0：核心闭环

- [x] 明确 Coze 工作流现有输入参数与输出字段（`meal_image` → `nutrition_report`）
- [x] 获取已发布工作流的 API 调用方式与一次真实 API 响应
- [x] 明确工作流内部包含“餐食识别”和“膳食分析”两个节点，但当前对外只返回最终文本
- [x] 确定两阶段人机协同方向：识别工作流 → Web 用户修正 → 分析工作流
- [x] 定义稳定的餐食识别与膳食分析 JSON 输出协议
- [x] 决定保留 V1 作为基线，新建识别工作流 V2 与分析工作流 V2
- [x] 创建 Streamlit Web 应用骨架
- [x] 实现餐食图片上传与预览
- [x] 实现文件类型、大小及基础可用性校验
- [x] 通过 HTTP API 调用 Coze 工作流
- [x] 展示 AI 餐食识别结果
- [x] 支持用户确认、修改、删除或补充识别食物
- [x] 使用用户最终确认的食物信息执行膳食结构分析
- [x] 展示餐食构成、膳食评价、主要问题和调整建议
- [x] 保持亲切、易懂、低压力且不限定年龄的表达风格
- [x] 实现加载、超时、失败、保留图片和重新分析状态
- [x] 增加图片判断局限及一般性饮食参考说明

- [x] 完成本地核心流程与四类识别分支测试

## Demo P2：扩展能力

- [ ] 生成结果分享卡片
- [ ] 支持减脂、增肌等个性化饮食目标
- [ ] 基于长期记录生成趋势总结
- [ ] 接入微信登录与用户身份
- [ ] 使用正式云数据库实现跨设备同步

## 明确不做

- [ ] 不根据单张图片输出缺乏可靠依据的精确克重
- [ ] 不根据单张图片输出缺乏可靠依据的精确热量或营养素数值
- [ ] 不提供疾病诊断、治疗方案或个体化医疗营养建议
- [ ] 不对图片无法确认的烹调方式、用油量和隐藏配料作确定性推断
