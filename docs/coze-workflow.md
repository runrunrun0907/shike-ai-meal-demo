# Coze 工作流现状

## 已确认信息

- 工作流状态：已发布。
- 开始节点输入：`meal_image`，类型为 `file`，含义为用户上传的餐食图片。
- 处理节点 1：`食物识别`，大语言模型节点。
- 处理节点 2：`营养分析`，大语言模型节点。
- 结束节点输出：`nutrition_report`，类型为 `string`。
- 输出定位：约 200–300 字的营养分析报告。

## 当前链路

`meal_image` → 食物识别 → 营养分析 → `nutrition_report`

## 样例输入

图片主要可见白粥、油条及粥面上的配料。部分细碎配料仅凭图片难以确定具体名称和烹调方式。

## 样例输出观察

当前输出具备以下优点：

- 语气亲切。
- 先总结整体结构，再提供三条调整建议。
- 建议包含具体替换食物，具有可执行性。

当前输出存在以下风险：

- 使用“叔叔阿姨”等特定人群称呼，与最新的一般用户定位不一致。
- 使用“太少”“不算很健康”等较强判断，可能增加用户压力。
- 从单张图片判断“好几种食材都是油炸制作”，证据可能不足。
- 将细碎配料确定为“炸酥碎”“蒜蓉/生蒜蓉”，可能存在识别或推断错误。
- “对血管和肠胃负担都比较大”等表达带有健康风险断言，不适合作为单餐图片结论。
- 输出为一个长字符串，前端难以分别展示识别结果、结构评价、问题与建议。

## 与 PRD 的差距

1. 当前链路虽有两个模型节点，但对外只返回最终报告，没有返回可编辑的食物列表。
2. 用户无法在营养分析前确认、修改、删除或补充识别结果。
3. 输出缺少稳定的结构化字段，无法可靠驱动多区块前端页面。
4. 缺少置信度或不确定食物表达。
5. 缺少明确的失败状态、不可分析状态和安全提示字段。

## 推荐改造方向

### 第一阶段：先完成可调用的最小版本

保留当前工作流，通过 HTTP API 接入 Streamlit，展示原始 `nutrition_report`，验证图片上传、调用、Loading、失败和结果展示流程。

### 第二阶段：改为两阶段人机协同

建议拆成两个可调用阶段：

1. 识别阶段：图片 → 结构化食物列表及不确定项。
2. 分析阶段：用户确认后的食物列表 → 结构化膳食分析与建议。

推荐输出字段：

```json
{
  "foods": [
    {
      "name": "白粥",
      "category": "主食",
      "confidence": "high"
    }
  ],
  "uncertain_items": [],
  "meal_summary": "",
  "main_issues": [],
  "suggestions": [],
  "limitations": "",
  "safety_note": ""
}
```

## 当前结论

现有 Coze 工作流足以作为 Web Demo 的第一个可运行后端，但尚不足以完整实现 PRD 中“先确认识别结果、再进行膳食分析”的 P0 人机协同流程。

## 架构决策（2026-08-26）

不继续在 V1 上叠加全部功能。保留原工作流作为基线和前后对比，新建 V2：

1. `meal_recognition_v2`：图片校验与餐食识别，返回结构化食物列表和不确定项。
2. Streamlit：展示识别结果，允许用户修改、删除和补充。
3. `meal_analysis_v2`：接收用户确认后的食物列表，返回结构化膳食评价和亲切建议。

历史记录、反馈和趋势不放进 Coze 工作流，由 Web 应用按 Demo P1/P2 逐步实现。

## V2 识别工作流验证记录（2026-08-26）

已搭建 `meal_recognition_v2`：

`meal_image` → 餐食识别（多模态 LLM）→ JSON 解析 → 结构化结束输出

调试过程与结论：

- 最初将模型生成的 JSON 作为单一 String 返回，出现外层引号与转义字符；通过 JSON 解析节点转为 Boolean、String、Array<Object> 等结构化字段。
- Doubao-Seed-1.8 对“不猜测模糊配料、识别项与不确定项去重”等长指令遵循不稳定。
- 使用版本标记验证实际运行配置，并切换至 Doubao-Seed-2.0-pro 后，同一测试图中仅将“白粥、油条”收入 `foods`，将绿色、棕红色及橙棕色碎料收入 `uncertain_items`。
- 当前正例已满足核心识别与不确定性表达要求；待补固定确认文案，并继续测试非食物、模糊图片等失败分支。

## Streamlit 联调里程碑（2026-08-27）

- `meal_recognition_v2` 已部署为 API 服务。
- Streamlit 已通过 Base64 Data URL 将本地上传图片直接传给部署接口，真实调用返回 HTTP 200。
- 页面已实现识别结果表格化展示，允许修改食物名称与类别、删除或新增项目，并在确认后保存最终食物列表。
- 已验证清晰餐食、非食物、严重模糊及主体缺失场景。
- 发现复合菜“番茄炒蛋”被归为“其他”等单标签分类限制；后续分析节点应结合菜名语义理解复合菜，不只依赖 category 字段。
- 里程碑截图：`docs/screenshots/streamlit-recognition-confirmed.png`。

## V2 分析工作流与完整链路（2026-08-27）

- `meal_analysis_v2` 已完成测试与 API 部署，输入为用户确认后的 `confirmed_foods`。
- 输出包含餐食结构、主要问题、可执行建议、亲切报告、分析限制和安全说明。
- Streamlit 已串联“图片识别 → 用户修正 → 结构分析”的完整 P0 人机协同链路。
- 页面只向分析接口传递食物名称和类别，避免识别置信度等无关字段影响判断。
